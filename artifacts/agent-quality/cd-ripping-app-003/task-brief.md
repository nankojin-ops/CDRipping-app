# Task Brief: アルバム単位メタデータ編集 & アルバムアート反映修正

- Task ID: `cd-ripping-app-003`
- リスク評価: **Medium**（ドメインモデル拡張、UIダイアログ新設、画像デコードとリサイズ、リッピングパイプライン結合）
- 対象ブランチ/コミット: `main` (ベース: `2897a50` + 既存のステージング前変更保持)

---

## 1. 要求の背景と目的

ユーザーからの要求：
1. **アルバム単位編集機能**: ディスク番号、アルバムアーティスト、アルバム名、リリース日、ジャンル、アルバムアートをアルバム単位で編集できるようにし、編集内容を全トラックへ一括反映する。
2. **iTunes APIアルバムアート反映の不具合修正**: iTunes APIからアルバム情報を取得した際にアルバムアートがメイン画面やエンコードに反映されない問題を修正する。

### 根本原因の事前分析 (iTunes API アートワーク不具合)
- iTunes API から返却される画像は JPEG 形式 (`.jpg`) であるが、UI (`app_view.py`) では `tk.PhotoImage(data=base64_data)` を直接呼び出していた。
- Tkinter 標準の `tk.PhotoImage` は PNG/GIF/PPM のみを解釈し、JPEG 形式を解釈できず `TclError: data stream does not have a PNG signature` が発生し、例外ハンドラで `_draw_no_artwork()` に倒れていた。
- 加えて、高解像度画像（1200x1200bb等）を 150x150 の Canvas 表示領域に収めるリサイズ（サムネイル化）処理が存在しなかった。

---

## 2. 要件定義

### 2.1 機能要件 (FR)
- **FR-001 (iTunesアートワーク反映修正)**:
  - iTunes APIから取得した画像バイナリ (JPEG/PNG) を Pillow (`PIL.Image`, `PIL.ImageTk`) を用いて安全にデコードし、150x150 の Canvas 領域にアスペクト比を維持してプレビュー表示する。
  - リッピング時にも取得したアルバムアートが全トラックのエンコードセッション（一時ファイル書き出し経由）に渡され、埋め込まれること。
- **FR-002 (アルバム単位編集ダイアログ)**:
  - メイン画面に「Edit Album Tags...」（アルバム情報編集）を起動するUIトリガー（ボタン等）を追加する。
  - モーダルダイアログで以下の全項目を表示・編集できること：
    - ディスク番号 (Disc No: 1〜999, Total Discs: 1〜999, 例: `1/1`, `1/2`)
    - アルバムアーティスト (`album_artist`: 最大256文字)
    - アルバム名 (`album`: 最大256文字)
    - リリース日 (`date` / year: 4桁年形式等)
    - ジャンル (`genre`: 最大256文字)
    - アルバムアート (`artwork`: 画像ファイルの選択、プレビュー表示、削除/クリア)
- **FR-003 (全トラックへの一括反映)**:
  - アルバム単位編集ダイアログで保存した際、管理されている全トラック（`track_tags` の全トラック）の対応フィールド（`disc_number`, `total_discs`, `album_artist`, `album`, `date`, `genre`）が一括更新されること。
  - アルバムアートが変更された場合、PresenterおよびUIに即時反映され、次回の全トラックリッピング時に新アートワークが適用されること。
  - 各トラック固有のタイトル (`title`) やトラック番号 (`track_number`), 個別アーティスト (`artist`) 等は壊さずに維持されること。
- **FR-004 (ドメインモデルおよびFFmpegタグ拡張)**:
  - `TrackTagData` に `album_artist: str = ""` を追加し、`to_metadata_dict()` で `-metadata album_artist="..."` に出力されるようにする。
  - `AlbumMetadata` に `album_artist` や変更追跡が正しく保持されること。

### 2.2 非機能要件 (NFR)
- **NFR-001 (安全性・バリデーション)**:
  - 不正なディスク番号（0以下、負数、NaN、1000以上、総数超過）は適切なエラーメッセージでブロックし、例外クラッシュを起こさないこと。
  - 特殊文字や制御文字（NULLバイト等）のサニタイズを実施すること。
- **NFR-002 (スレッド安全性)**:
  - UIスレッドでの画像処理・ダイアログ操作がバックグラウンドリッピングやイベントキューと競合しないこと。
- **NFR-003 (リソース解放・メモリリーク防止)**:
  - 選択された画像や一時ファイル、Tkinterオブジェクトが適切に解放・破棄されること。

### 2.3 制約事項
- 既存のテストスイート（100件）の回帰テストをすべて維持・合格すること。
- `git reset --hard` や破壊的ファイル操作は厳禁。
- 外部追加ライブラリは環境に既存の `Pillow` (PIL) のみを使用し、新たなパッケージ追加を不要とする。

## 3. 検証可能な受入条件 (Acceptance Criteria)

- **AC-001 (iTunesアートワークプレビュー表示)**:
  iTunes APIからアルバム情報（JPEG画像含む）を取得した際、メイン画面のArtworkキャンバスに縮小されたカバーアートが正しくプレビュー表示されること。
- **AC-002 (アルバム単位編集ダイアログ)**:
  メイン画面からアルバム編集ダイアログを開き、ディスク番号・アルバムアーティスト・アルバム・リリース日・ジャンル・アルバムアートの各項目を編集できること。
- **AC-003 (全トラック一括反映)**:
  アルバム単位編集ダイアログで保存を実行した際、全トラックのタグ情報（disc, album_artist, album, date, genre）およびアルバムアートが一括更新され、トラック一覧および個別タグ編集ダイアログでも反映後の値が確認できること。
- **AC-004 (アルバムアートの選択・変更・クリア)**:
  アルバム編集ダイアログ（またはメイン画面）からローカル画像（JPEG/PNG）を選択して設定、またはクリアでき、プレビューおよびリッピング生成ファイルに反映されること。
- **AC-005 (エンコードタグ埋め込み検証)**:
  アルバム編集で設定した `album_artist` や更新された `disc`, `date`, `genre`, `album`、およびアルバムアートが、生成された音声ファイル（AAC/MP3/ALAC等）のメタデータに正しく埋め込まれること。
- **AC-006 (既存機能の無回帰)**:
  個別トラックタグ編集ダイアログ (`TrackTagEditDialog`)、リッピングパイプライン、SPTI/VirtualCDドライブの全100件のテストがパスし、機能破壊がないこと。
